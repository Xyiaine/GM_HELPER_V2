A.1 - OBJECTIF DE L'APPLICATION

Créer une application web fullstack permettant à un Maître du Jeu (MJ) de
gérer intégralement une campagne de jeu de rôle sur table dans un univers
post-apocalyptique original : personnages, PNJ, lieux, cités, cartes
interactives, quêtes, objets, rencontres/combats, convois, véhicules,
arbres de compétences, notes de campagne et mode session live.

L'application se compose de TROIS INTERFACES DISTINCTES :

  1. INTERFACE MJ (usage principal : ordinateur / desktop)
     -> Accès complet à tout le contenu de la campagne (voir Partie E)

  2. INTERFACE JOUEUR (usage principal : mobile / smartphone)
     -> Accès STRICTEMENT LIMITE (voir Partie F) :
        a) Consultation et édition (si autorisée) de SA PROPRE fiche
           de personnage et de ses arbres de compétences
        b) Lancers de dés dont les modificateurs sont calculés
           automatiquement par le serveur
        c) Vue session live (PV, tour d'initiative, bannière Spotlight)
        d) Vue convoi en cours (lecture seule)

  3. VUE ECRAN TABLE / TV (/table/:token)
     -> Affichage partagé pour l'écran central de la table de jeu :
        bannières Spotlight, images de PNJ/Lieux, initiative live.

A.2 - UTILISATEURS ET ROLES

- GM (Game Master / Maître du Jeu) : contrôle total sur sa/ses campagne(s).
- PLAYER (Joueur) : accès restreint tel que défini en A.1 et Partie F.

Un utilisateur peut être MJ d'une campagne et joueur dans une autre. Le
rôle est défini PAR CAMPAGNE via la table `CampaignMembership`.

PARTIE C - ARCHITECTURE TECHNIQUE (ETAT REEL DU CODE)
========================================================================

C.1 - VUE D'ENSEMBLE

Application web fullstack monorepo avec :
- /client : Frontend React (Vite)
- /server : Backend Node.js + Express + Socket.IO + Prisma
- /scripts : Utilitaires (extraction lore, fix Prisma)

C.2 - STACK TECHNIQUE UTILISEE

--- Frontend (client/) ---
- Framework : React 18 avec architecture par composants
- Build tool : Vite 5 avec Hot Module Replacement (HMR)
- Gestion d'état : Zustand 4.5 (authStore, gmStore, playerStore)
- Routing : React Router DOM 6 avec lazy loading sur GmApp, PlayerApp et TableScreenView
- Icônes : Lucide React
- WebSocket client : socket.io-client 4.7
- Styling : Vanilla CSS avec variables CSS (thème sombre, tokens)

--- Backend (server/) ---
- Runtime : Node.js avec Express 4
- ORM : Prisma 6.9 avec SQLite (dev.db)
- Authentification : JWT (jsonwebtoken 9) avec access token + refresh token (cookie httpOnly)
- Hashage : bcrypt (12 rounds)
- Validation : Zod 3.24 (validators/schemas.js)
- Temps réel : Socket.IO 4.8
- Upload fichiers : Multer (stockage local dans /uploads)
- Sécurité : Helmet 8, express-rate-limit 7, CORS, cookie-parser

PARTIE E - SPECIFICATIONS FONCTIONNELLES DETAILLEES (INTERFACE MJ)
========================================================================

E.1 - GESTION DE CAMPAGNES ✅
- CRUD complet de campagnes et invitation de joueurs.

E.2 - FICHES DE PERSONNAGES & CLASSES HYBRIDES ✅
- Fiche de personnage D&D 5e personnalisée.
- Progression hybride : 16 arbres de compétences (7 de base + 9 de factions).
- Niveaux dynamiques calculés par hybridProgression.js selon l'investissement de points.

E.3 - MOTEUR ET EDITEUR DE QUETES (QuestGraphEditor) ✅
- **Description Sensorielle Unifiée** : Un grand champ texte unique (`rows={8}`) *"Description Sensorielle (Ce que voient les joueurs)"* centralise tous les éléments d'ambiance visuelle, sonore et olfactive.
- **Support des 10 extensions v3** :
  1. `detectionMechanic` (JSON pour indices et jets de danger)
  2. `pathGroup` (regroupement visuel des branches)
  3. `displayCode` (code lisible ex: "0.a", "2A.e")
  4. `isOptional` & `pacingTag` (rythme et scènes facultatives)
  5. `QuestNodeReward` (butin par étape)
  6. `QuestThreatTracker` (horloge de menace type "Ver des Sables")
  7. `QuestFactionProgress` (suivi des convois rivaux)
  8. `QuestCharacterState` (mémoire et états individuels par PJ)
  9. `requiredSkillCategory` (audit des compétences sollicitées)
  10. Minuteurs de nœuds avec exécution de nœud de conséquence (`timeoutNodeId`)
- **Spotlight Broadcast** : Diffusion en 1 clic de la description sensorielle ou d'images sur les écrans partagés des joueurs et l'écran de table.

E.4 - SYSTEME DE CONVOIS ✅
- Génération procédurale d'événements (`convoyGenerator.js`, 100+ biomes).
- Gestion des 5 jauges de ressources (carburant, eau, nourriture, médicaments, munitions), état des véhicules et cargaison.

E.5 - SYSTEME DE VEHICULES MODULAIRES ✅
- Pièces interchangeables (châssis, moteur, NOS, armes) avec modificateurs et usure.
- Rôles d'équipage (pilote, tireur, ingénieur) et attribution des accès.

E.6 - CITES-ETATS & IMPACTS AUTOMATIQUES ✅
- 7 paramètres (0-100) affectés automatiquement par la réussite/échec des quêtes (`QuestCityImpact`).

E.7 - CARTES ET MARKERS ✅
- Carte du monde interactive Canvas avec polygones de territoires de cités.
- Cartes locales avec marqueurs polymorphes (PNJ, Lieux, Quêtes).

E.8 - AUTRES MODULES MJ ✅
- Combat Tracker, Gestion d'Objets, Notes hiérarchiques, Tags, Liens universels, Recherche globale, Session Manager.
